# 플레이 제라 — 캐릭터 성장 기획

> 초안 2026-08-05 · 컨셉아트 확정 시점
> 기획안 v4(`docs/01`)의 "2단계 — 아이 관리"를 구체화한 문서다.

---

## 0. 한 문단 요약

아이는 **알 하나**로 시작한다. 몸을 움직여 게임을 하면 알이 깨어나고, 친구가 자란다.
**자라는 연료는 점수가 아니라 운동량이다.** 형태가 바뀔 수 있게 되면 갈아입을 수 있지만,
**바꿀지 말지는 아이가 정한다.**

---

## 1. 네 축을 분리한다 — 레벨 · 형태 · 아이템 · 배지

이 넷을 섞으면 나중에 반드시 꼬인다. 처음부터 따로 둔다.

| 축 | 무엇으로 | 누가 정하나 | 누구에게 보이나 |
|---|---|---|---|
| **레벨** | 운동량이 쌓이면 자동으로 | 시스템 | 아이 |
| **형태** | 레벨이 문턱을 넘으면 **해금** | **아이가 골라 입는다** | 아이 |
| **아이템** | 특정 운동을 해내면 획득 | 아이가 골라 장착 | 아이 |
| **배지** | 특정 운동을 해내면 획득 | — (그냥 쌓인다) | **아이 + 부모** |

레벨은 되돌릴 수 없고, 형태와 아이템은 언제든 바꿀 수 있고, 배지는 지워지지 않는다.
이 구분이 아래 모든 결정의 근거다.

---

## 2. 변신은 선택이다 — **다만 되돌릴 수 있게** ★

ken의 제안: "알에서 깬 모습이 좋으면 그대로 키울 수 있게 하자."
**방향은 맞다. 한 가지만 바꾸면 훨씬 좋아진다 — 한 번 고르면 끝이 아니라, 언제든 갈아입게 한다.**

### 왜 선택권이 맞나

- 아이는 **처음 본 모습에 정든다.** 강제로 변신시키면 친구를 잃은 기분이 든다.
  (포켓몬에 '만능돌'이 있는 이유가 정확히 이것이다)
- 4~8세가 이 게임에서 내리는 결정이 거의 없다. 대부분 화면이 시키는 대로 몸을 움직인다.
  **자기가 정하는 지점이 하나 있는 것과 없는 것은 애착에서 큰 차이가 난다.**
- 같은 공룡을 둘 키워도 서로 다른 모습이 된다 — **새 그림 없이 개성이 생긴다.**

### 왜 "한 번 고르면 끝"은 위험한가

- **되돌릴 수 없는 선택은 4~8세에게 이르다.** 뜻을 모르고 "아니"를 눌렀다가
  나중에 후회하면 그때는 방법이 없다. 우는 아이가 생긴다.
- 더 큰 문제는 **보상이 사라진다는 것**이다. 변신은 운동에 대한 가장 눈에 띄는 보상인데,
  아이가 거절하면 레벨 20에서 40이 되는 동안 화면에서 바뀌는 게 없다.
  운동 데이터가 목적인 서비스에서 이건 그냥 동기 상실이다.

### 그래서 — **해금하되 강요하지 않는다**

```
레벨이 문턱을 넘음  →  새 형태가 "열렸어요!"  (보상은 여기서 확실히 준다)
                    →  지금 갈아입을래?  [응] [나중에]
                    →  언제든 캐릭터 화면에서 서로 바꿀 수 있다
```

이러면 셋 다 얻는다.

- **보상이 유지된다** — 해금 자체가 사건이고 축하 연출이 붙는다
- **자율성이 유지된다** — 안 입어도 되고, 알 모습 그대로 레벨 40이 될 수 있다
- **후회가 없다** — 마음이 바뀌면 도로 갈아입는다

> 형태는 **옷**이지 운명이 아니다. 이 한 줄이 이 기획의 핵심이다.
> 구현도 단순해진다 — `unlockedForms: []`와 `currentForm` 두 필드면 끝난다.

---

## 3. 레벨은 무엇으로 오르나 — **운동량이다**

**점수로 올리면 안 된다.** 점수로 올리는 순간 아이는 점수를 잘 내는 법을 찾고,
그건 대체로 "덜 움직이는 법"이다. 실제로 똥 피하기의 `dodgeCount`는 가만히 서 있어도 오른다.

이미 저장하고 있는 것들이 그대로 연료다(`exercise_summary`).

| 재료 | 지금 쌓이나 |
|---|---|
| 활동 시간 `active_sec` | ✅ |
| 좌우 이동 `side_steps` | ✅ |
| 점프 `jumps` | ✅ (웜업) |
| 앉기 `squats` | ✅ (웜업) |
| 포즈 유지 `pose_holds` | ✅ (웜업) |

**게임을 끝까지 못 깨도 오른다.** 40초를 뛰었으면 40초만큼 오른다.
"잘해야 보상"이 아니라 "움직이면 보상"이어야 매일 하게 된다.

> ⚠️ 지금은 게임을 다 끝내야만 기록이 저장된다. 중간에 그만두면 아무것도 안 남는다.
> 레벨 시스템을 붙이기 전에 **이탈 시 저장**을 먼저 고쳐야 한다.
> (`docs/04` STEP 8 — 똥 피하기 '다시 시작' 논의와 같은 문제다)

### 운동 종류를 섞게 만든다

한 가지 운동만 반복하면 레벨이 천천히 오르게 한다. 좌우 이동만 3000번 하는 것보다
여러 종류를 고루 하는 편이 몸에 좋고, 게임 여러 개를 돌게 만드는 효과도 있다.

## 4. 단계를 늘릴까, 아이템을 넣을까 — **아이템이 낫다**

지금 4단계(알 → 부화 → 1단계 → 2단계/히어로)는 짧다. 늘리는 선택지가 둘이다.

| | 비용 | 얻는 것 |
|---|---|---|
| 단계 추가 | 캐릭터 × 단계마다 **새 그림 한 장씩** | 선형으로 는다 |
| 아이템 | 아이템당 그림 하나 (전 캐릭터 공용 가능) | **조합으로 는다** |

아이템 10종이면 3캐릭터 × 4형태 × 10 = 조합이 폭발한다. 그림은 10장만 그렸는데.
**단계 추가는 선형, 아이템은 곱셈이다.** 그림 비용이 곧 개발 속도인 지금은 아이템이 맞다.

### 아이템은 "운동의 종류"에 붙인다

아이템을 그냥 레벨 보상으로 주면 결국 시간 싸움이다. 대신 **무엇을 했는지**에 붙인다.

```
점프 500번    → 용수철 신발
포즈 100번    → 마법 지팡이
5일 연속 놀기 → 반짝이는 망토
게임 3종 완주 → 탐험가 배낭
```

이러면 아이템이 **"어떤 운동을 더 해볼까"의 안내판**이 된다.
운동 다양성이 늘고, 그게 그대로 더 나은 운동 데이터가 된다.

## 4-1. 배지 — 아이가 자랑하고, 부모가 읽는다 ★

아이템과 조건이 비슷해서 헷갈리기 쉽다. **역할이 다르다.**

| | 아이템 | 배지 |
|---|---|---|
| 어디에 | 캐릭터가 입는다 | 목록에 쌓인다 |
| 바뀌나 | 벗었다 입었다 | **영원히 남는다** |
| 누가 읽나 | 아이 | **아이 + 부모** |

배지가 하는 일이 셋 있다.

**1. 부모가 읽을 수 있는 유일한 화면이다.**
"레벨 14"는 부모에게 아무 뜻이 아니다. **"점프 20회 달성"은 문장이다.**
학부모 리포트(3단계)의 씨앗이 여기 있다 — 배지 목록이 곧 "이 아이가 무엇을 했는가"다.

**2. 지워지지 않는다.**
형태는 갈아입고 아이템은 벗는데, 배지는 쌓이기만 한다. 트로피 선반의 감각이다.

**3. 레벨로는 표현 못 하는 것을 담는다.**
"연속 6일"은 운동량 합계로는 표현이 안 된다. 배지만 할 수 있다.

### 조건 엔진은 하나, 결과는 둘

아이템과 배지의 조건이 겹친다(둘 다 "점프 500번" 같은 것). **조건을 두 벌 만들지 않는다.**

```
운동 기록이 쌓임 → 조건 하나가 충족 → 배지 지급 (+ 어떤 조건은 아이템도)
```

배지는 촘촘하게, 아이템은 드물게. **모든 배지가 아이템을 주면 캐릭터가 잡동사니를 뒤집어쓴다.**

### ⚠️ 목업의 "피하기 30회"는 운동이 아니다

똥 피하기의 `dodgeCount`는 **가만히 서 있어도 오른다.** 다른 칸에 떨어지면 세니까.
이 배지를 그대로 넣으면 **안 움직이는 아이에게 상을 주게 된다.**

이미 같은 이유로 운동 데이터에서는 `side_steps`(실제로 자리를 옮긴 횟수)만 쓰고 있다
(`docs/04` STEP 8). 배지도 같은 기준을 써야 한다.

```
✗ 피하기 달인 — 피하기 30회      ← 서 있어도 달성된다
✓ 날쌘돌이   — 옆으로 30번 피하기  ← 실제로 몸을 옮겨야 한다
```

**다른 넷은 그대로 좋다** — 점프·포즈·활동일수는 전부 몸을 움직여야 오르는 값이다.

### ⚠️ "연속 출석"은 이 나이대에 조심해야 한다

`연속 활동 6일` · `3일 연속 출석`은 강력한 장치지만, **4~8세에게는 위험이 있다.**

- 아이는 **자기가 놀 수 있는지를 못 정한다.** 아프거나, 여행 가거나, 부모가 바쁘면 끊긴다
- 자기 잘못이 아닌 일로 기록이 사라지면 **벌처럼 느껴진다**
- 끊기지 않으려고 부모를 조르게 되는 것도 원하는 그림이 아니다

**연속 대신 "기간 안에 몇 번"으로 센다.**

```
✗ 3일 연속 출석            ← 하루 빠지면 0으로
✓ 이번 주에 3일 놀기        ← 월·수·금이어도 된다
✓ 이번 달에 10일 놀기
```

> **결정됨 (2026-08-05)** — 출석 배지는 넣는다. 다만 문구를 "연속"이 아니라
> "이번 주에 n일"로 쓴다. `daysInWindow` 조건이 이걸 그대로 표현한다.

같은 "꾸준함"을 재면서 벌은 없다. 하루 빠져도 이번 주는 아직 살아 있다.
**습관을 만들려는 것이지, 안 빠지기 시합을 시키려는 게 아니다.**

### 배지 갈래

| 갈래 | 예 | 재료 |
|---|---|---|
| 동작 | 점프 챔피언 · 포즈 히어로 · 날쌘돌이 | `jumps` · `pose_holds` · `side_steps` |
| 시간 | 10분 놀기 · 100분 놀기 | `active_sec` |
| 꾸준함 | 이번 주 3일 · 이번 달 10일 | 논 날짜 |
| 탐험 | 게임 3종 다 해보기 | 게임별 기록 유무 |
| 성장 | 첫 부화 · 첫 변신 | 캐릭터 상태 |

**첫 배지는 첫날에 준다.** 첫 판을 끝내면 바로 하나 — "오늘 처음 놀았어요".
첫 보상이 멀면 그전에 그만둔다. 부화까지 하루 이틀로 잡은 것과 같은 이유다.

### 어디에 보이나

- **게임 끝난 직후** — 새로 딴 배지가 있으면 결과 화면에서 축하한다. 여기가 제일 크게 와닿는다
- **허브 `👤 제라` 화면** — 목록. 목업처럼 최근 5개 + `더 보기`
- **학부모 리포트(3단계)** — 배지 목록이 그대로 요약이 된다

## 5. 유료화 — 하나는 무료, 더 키우려면 결제

방향은 동의한다. 다만 **파는 방식**에 두 가지 원칙을 둔다.

**1. 돈으로 빨리 자라게 하지 않는다.**
결제한 아이가 더 빨리 레벨업하면 운동 데이터가 오염되고,
"움직여서 자란다"는 이 서비스의 약속이 깨진다. **파는 것은 자리(슬롯)이지 속도가 아니다.**

**2. 지갑을 여는 사람은 부모다.**
아이에게는 "친구를 더 모으자"이지만, 부모에게 하는 말은 달라야 한다.
> "아이가 질려서 안 하기 시작할 때, 새 친구 하나가 다시 움직이게 만듭니다."

수집욕이 아니라 **지속성**을 판다. 운동 리포트(3단계)와 묶으면 설득력이 더 생긴다.

## 6. 지금 배포에 넣을 것 / 나중에 할 것

핵심 게임 루프가 아직 실기기 검증 중이다. **성장 시스템 전체를 지금 붙이면
게임이 이상할 때 원인이 게임인지 성장 시스템인지 갈리지 않는다.** 두 단계로 나눈다.

### 1차 — 지금 (계정 없이, localStorage로)

- 프로필 고르기: 남자아이 / 여자아이 (컨셉아트 그대로)
- 알 고르기: 식물 / 공룡 / 토끼 **하나**
- 운동량이 쌓이면 **부화**까지만 (알 → 부화)
- 홈 화면에 내 친구가 보인다
- **배지 몇 개** — 첫날 하나, 동작 배지 서넛, 주간 꾸준함 하나

부화 하나만으로도 "며칠 더 해볼까"가 생긴다. **첫 보상까지 걸리는 시간을 짧게 잡는다** —
하루 이틀 안에 알이 깨야 한다. 일주일이면 그전에 그만둔다.

> 배지를 1차에 넣는 이유 — **조건 엔진을 일찍 만들어두면 아이템이 거저 붙는다.**
> 둘이 같은 조건을 쓰기 때문이다. 배지로 먼저 검증하고 아이템은 나중에 얹는다.

### 2차 — 계정 이후

- 1단계 · 2단계 해금 + **형태 갈아입기**
- 아이템
- 캐릭터 슬롯 추가(유료)

> `core/player.js`가 지금은 "브라우저 하나 = 한 명"이다. 캐릭터 상태를 여기 붙여두면
> 계정이 생길 때 이 파일 하나만 Supabase로 바꾸면 된다. **화면은 손대지 않는다.**

## 7. 늘어나도 안 무너지게 — 데이터로 두고 코드는 고정한다 ★

캐릭터도 배지도 아이템도 **계속 늘어난다.** 늘 때마다 화면 코드를 고쳐야 하면 오래 못 간다.

이미 검증된 방법이 있다 — `games/registry.js`다. **게임을 추가할 때 손대는 파일이 하나다.**
라우터도 허브도 게임 이름을 모른다. 같은 방식을 그대로 쓴다.

```
버디를 추가한다  → 폴더 하나 + manifest 하나
배지를 추가한다  → 목록에 한 줄
아이템을 추가한다 → 목록에 한 줄
                  ↑ 화면 코드는 건드리지 않는다
```

### 7-1. 말부터 정리한다 — "캐릭터"가 세 가지를 가리키고 있다

지금 세 가지가 전부 "캐릭터"로 불린다. 이대로 두면 폴더도 코드도 반드시 엉킨다.

| 부를 이름 | 무엇 | 누가 소유 |
|---|---|---|
| **프로필** `profile` | 남자아이 / 여자아이 아바타 | 계정 |
| **버디** `buddy` | 알에서 키우는 친구 (식물·공룡·토끼) | 계정 |
| 게임 스프라이트 | 똥 피하기의 노란 곰 등 | **게임팩** |

> ⚠️ `public/assets/characters/`는 **이미 똥 피하기 스프라이트가 쓰고 있다.**
> 여기에 버디를 넣으면 섞인다. 버디는 `buddies/`로 따로 둔다.
> (똥 피하기 스프라이트는 나중에 게임팩 폴더로 옮기는 게 맞지만 급하지 않다)

### 7-2. 폴더 구조 — 에셋 작업 기준

```
public/assets/
  buddies/
    plant/            식물
      egg.png
      hatch.png
      grow.png
      hero.png
    dino/             공룡
      egg.png  hatch.png  grow.png  hero.png
    bunny/            토끼
      egg.png  hatch.png  grow.png  hero.png
  profiles/
    girl.png
    boy.png
  badges/
    first_play.png
    jump_20.png
    ...
  items/              (2차)
    spring_shoes.png
```

**버디마다 폴더 하나, 파일 이름은 어느 버디든 똑같다.** 그래서 경로를 코드가 계산한다.

```
/assets/buddies/{버디id}/{단계}.png
```

`plant_egg.png` 처럼 평평하게 두지 않는 이유 — 버디가 10종이 되면 파일 40개가
한 폴더에 섞이고, `dino_lv1.png` / `bunny_level1.png` 처럼 이름이 어긋나기 시작한다.
**폴더로 나누면 이름이 어긋날 자리가 없다.**

### 7-3. 파일 이름 규칙

| 무엇 | 규칙 | 예 |
|---|---|---|
| 버디 단계 | `egg` · `hatch` · `grow` · `hero` | `dino/grow.png` |
| 프로필 | `{성별}.png` | `girl.png` |
| 배지 | `{배지id}.png` — 카탈로그의 id와 **같아야** 한다 | `jump_20.png` |
| 아이템 | `{아이템id}.png` | `spring_shoes.png` |

- **소문자 + 밑줄만.** 한글·공백·대문자는 쓰지 않는다(경로 인코딩 문제가 난다)
- **PNG는 투명이 필요할 때만.** 배경이 꽉 찬 그림은 JPG (키아트 2.4MB → 278KB 사례 참고)
- **버디 그림은 세로 512px 안쪽**이면 충분하다. 화면에서 그보다 크게 안 쓴다

> **순서와 해금 레벨은 파일 이름이 아니라 manifest가 정한다.**
> 그래서 나중에 단계를 끼워 넣어도(`grow2.png` 같은 것) 이름이 꼬이지 않는다 —
> 배열에 한 줄 더하면 화면은 그대로 따라간다.

### 7-4. 버디 manifest — 단계가 늘어도 코드는 그대로

```jsonc
// src/buddies/dino/manifest.json
{
  "id": "dino",
  "name": "아기 공룡",
  "tagline": "씩씩한 친구",
  "stages": [
    { "id": "egg",   "label": "알",     "image": "egg.png",   "unlockLevel": 0 },
    { "id": "hatch", "label": "아기",   "image": "hatch.png", "unlockLevel": 1 },
    { "id": "grow",  "label": "친구",   "image": "grow.png",  "unlockLevel": 5 },
    { "id": "hero",  "label": "히어로", "image": "hero.png",  "unlockLevel": 12 }
  ]
}
```

**단계를 늘리려면 배열에 한 줄 + 그림 한 장.** 화면은 배열을 그대로 그리므로 손댈 게 없다.
버디를 늘리려면 폴더 하나 + `src/buddies/registry.js`에 한 줄.

### 7-5. 배지·아이템 — 조건을 **데이터로** 적는다

조건을 코드로 짜면 배지 하나 추가할 때마다 함수가 하나씩 는다. **조건의 종류를 몇 개로
고정하고, 배지는 그 종류에 값만 채운다.**

```js
// src/progress/badges.js
{ id: 'first_play',  name: '첫 걸음',      desc: '처음 놀았어요',
  cond: { kind: 'total', metric: 'sessions', n: 1 } },

{ id: 'jump_20',     name: '점프 챔피언',   desc: '점프 20회 달성',
  cond: { kind: 'total', metric: 'jumps', n: 20 } },

{ id: 'week_3',      name: '꾸준한 최고!',  desc: '이번 주에 3일 놀기',
  cond: { kind: 'daysInWindow', days: 7, n: 3 } },

{ id: 'explorer',    name: '탐험가',        desc: '게임 3종 다 해보기',
  cond: { kind: 'variety', of: 'games', n: 3 } },

{ id: 'first_hatch', name: '알이 깨졌다!',  desc: '친구를 만났어요',
  cond: { kind: 'event', event: 'hatch' } },
```

조건 종류는 넷이면 거의 다 덮는다.

| kind | 뜻 | 덮는 것 |
|---|---|---|
| `total` | 누적값이 n 이상 | 점프·포즈·좌우이동·활동시간·판수 |
| `daysInWindow` | 최근 D일 중 n일 놀았나 | 출석·꾸준함 |
| `variety` | 서로 다른 것 n종 | 게임 3종·포즈 3종 |
| `event` | 특정 사건이 일어났나 | **운동이 아닌 것** — 첫 부화·첫 변신·버디 고르기 |

**`event`가 "운동 이외의 보상"을 담는 자리다.** ken이 말한 출석·특별한 순간이 여기 들어간다.

배지를 추가한다 = 위 목록에 **한 줄 + 아이콘 한 장.** 코드는 안 건드린다.
새 `kind`가 필요한 건 드물고, 그때만 평가 함수에 분기가 하나 는다.

아이템도 같은 모양에 `slot`만 더 붙인다.

```js
{ id: 'spring_shoes', name: '용수철 신발', slot: 'feet',
  cond: { kind: 'total', metric: 'jumps', n: 500 } }
```

> **조건 엔진은 하나다.** 배지와 아이템이 같은 평가기를 쓴다.
> 한 번 만들어두면 아이템은 목록만 추가하면 붙는다.

## 8. 개발 순서

### 0단계 — 먼저 막아야 할 구멍 ⚠️

**중간에 그만두면 아무것도 저장되지 않는다.** 지금은 게임을 끝까지 깨야만 기록이 남는다.
이 상태로 레벨·배지를 붙이면 **아이가 움직인 만큼 세어지지 않는다.**

성장 시스템의 모든 숫자가 이 기록 위에 서 있으므로, 이걸 먼저 고친다.
(`docs/04` STEP 8 — 똥 피하기 '다시 시작' 논의와 같은 문제)

### 1단계 — 뼈대 ✅ (2026-08-05)

파일과 실측값은 아래 표 다음에 정리했다.



| 파일 | 하는 일 |
|---|---|
| `src/progress/stats.js` | 누적 통계 모으기 (Supabase `exercise_summary` + 로컬) |
| `src/progress/conditions.js` | 조건 평가 — **순수 함수, 테스트 대상** |
| `src/progress/badges.js` | 배지 목록 (데이터) |
| `src/progress/level.js` | 운동량 → 레벨 환산 |
| `src/buddies/registry.js` | 버디 목록 + manifest 로더 |

**게임 코드를 하나도 안 건드렸다.** 웜업 포즈 검증이 걸려 있어도 병행됐다.
조건 평가는 순수 함수라 몸 없이, 그림 없이 검증된다.

#### 실측 — EXP 저울이 맞는가

```
똥 피하기 1판 (150초 + 좌우 40)          = 190 EXP
웜업 1판      (50초 + 점프6 앉기4 좌우7)  =  77 EXP

LV1 문턱 300  →  실제로 3판 만에 부화
```

**목표였던 "하루 이틀 안에 부화"에 맞는다.** 하루 두세 판이면 이튿날 알이 깨진다.

레벨 문턱: 300 → 705 → 1252 → 1990 → 2986 (`BASE 300`, `GROWTH 1.35`)

#### 지켜야 할 규칙을 테스트가 붙들고 있다

| 규칙 | 왜 |
|---|---|
| 점수·`dodges`는 EXP가 되지 않는다 | 가만히 서 있어도 오르는 값이다 |
| 꾸준함 배지는 전부 `daysInWindow` | "연속"이 섞여 들어오는 걸 막는다 |
| 게이지 문구에 숫자가 없다 | 숫자를 못 읽는 아이를 위한 문구다 |
| 모르는 조건은 **미달성** | 참으로 처리하면 배지가 우수수 열린다 |
| 안 열린 형태를 고르면 열린 것으로 폴백 | 잘못된 값 때문에 빈 화면이 되면 안 된다 |
| 깨진 저장본·옛 저장본도 읽힌다 | 필드가 늘어도 예전 아이가 초기화되지 않는다 |

> 버디 파일 이름은 `egg` · `hatch` · `grow` · `hero`로 확정(2026-08-05).
> **순서와 해금 레벨은 manifest가 정하므로** 나중에 단계를 끼워 넣어도 이름이 안 꼬인다.

### 2단계 — 화면

| 화면 | 내용 |
|---|---|
| 첫 실행 | 프로필 고르기 → 알 고르기 (부화 전까지 바꿀 수 있게) |
| 허브 `👤 제라` | 내 버디 + 레벨 + 배지 목록 (최근 5개 + 더 보기) |
| 게임 결과 | 새로 딴 배지 축하 · 레벨 오름 표시 |
| 허브 홈 | 내 버디가 한쪽에 보인다 |

### 3단계 — 계정 이후

형태 갈아입기 · 아이템 · 버디 슬롯 결제 · 학부모 리포트

> `core/player.js`가 지금 "브라우저 하나 = 한 명"이다. 버디·배지 상태를 이 뒤에 두면
> 계정이 생길 때 이 파일만 Supabase로 바꾸면 된다. **화면은 손대지 않는다.**

## 10. 이 기획이 서비스 목적과 맞는가

`CLAUDE.md` 첫 줄 — **"운동 데이터가 쌓이는 것이 이 서비스의 존재 이유다."**

이 기획의 모든 장치가 그 한 줄을 향한다.

- 레벨을 **운동량**으로 올린다 → 점수 파밍이 무의미해진다
- 아이템을 **운동 종류**에 붙인다 → 여러 방식으로 움직이게 된다
- 형태를 **갈아입게** 한다 → 애착이 생기고, 애착은 내일 다시 오게 만든다
- 결제로 **속도를 팔지 않는다** → 데이터가 오염되지 않는다
- 배지를 **부모가 읽을 수 있게** 쓴다 → 운동 기록이 그대로 리포트가 된다

캐릭터는 운동을 꾸미는 장식이 아니라, **아이가 내일 또 움직일 이유**다.
