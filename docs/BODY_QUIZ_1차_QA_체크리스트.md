> 기준 worktree: `kunbrostudio/body-quiz`<br>
> 작성일: 2026-09-14<br>
> 목적: 기능을 확장하지 않고, 현재 카메라 기반 BODY QUIZ가 실제 환경에서 한 판 성립하는지 확인한다.

## 0. 이번 QA 범위

### 포함

- 문제 문장 표시
- 좌우 답안 이미지와 라벨 표시
- 스쿼트 카운트
- MOVE ENERGY 증가
- MOVE LOCK → MOVE UNLOCK 전환
- LEFT / CENTER / RIGHT zone 및 답 선택·정오답 처리
- 시스템 메뉴와 종료 확인 팝업

현재 문제 데이터는 1개다. 한 세션은 `QUIZ 1 / 1`이며 정답인 코끼리의 LEFT/RIGHT
위치는 세션마다 무작위다. 답을 확정한 뒤 결과가 유지되면 현재 데이터 기준 정상이다.

### 제외

- 캐릭터 응원 UI
- 말풍선 시스템
- 사용자에게 보이는 타이머
- 스쿼트 이외 운동 종류
- 정식 운동 아이콘 교체
- 문제/카테고리 추가 및 점수·결과 화면 설계

지정된 `guide_girl.png`, `guide_boy.png`가 아직 없으므로 캐릭터와 말풍선은 코드에서
숨김 처리된다. 이번 QA에서는 해당 영역의 표시 여부를 결함으로 판정하지 않는다.

## 1. 테스트 배포 사전 조건

- 현재 BODY QUIZ 소스/에셋/테스트와 이 QA 문서는 Git에서 untracked이고 registry 등록도
  미커밋 상태다. 로컬 빌드는 되지만 **Git 기반 branch preview에는 아직 포함되지 않는다.**
  배포 승인을 받은 뒤 BODY QUIZ 대상만 명시적으로 stage/commit해야 하며, unrelated
  balloon-festival 파일에 `git add .`를 사용하지 않는다.
- Netlify build command: `npm run build`
- publish directory: `dist`
- 필요한 환경 변수 키:
  - `VITE_SUPABASE_URL`
  - `VITE_SUPABASE_ANON_KEY`
- BODY QUIZ manifest가 현재 `status: "wip"`이므로 production/branch preview의 허브
  카드 목록에는 나오지 않는다. 1차 QA는 아래 직접 URL을 공유한다.
  - 인트로부터: `https://<preview-host>/#/intro?id=body-quiz`
  - 튜토리얼 강제 표시: `https://<preview-host>/#/intro?id=body-quiz&tutorial=1`
  - 플레이 직접 진입: `https://<preview-host>/#/play?id=body-quiz`
- 카메라는 HTTPS 또는 브라우저가 예외로 인정하는 `localhost`에서만 사용할 수 있다.
  IP 주소의 평문 HTTP 접속은 모바일 카메라 QA에 사용하지 않는다.
- 배포 응답 헤더의 `Permissions-Policy`가 `camera=(self)`인지 확인한다.
- 포즈 엔진 첫 실행에는 다음 외부 리소스 접근이 필요하다. 학교/기관 Wi-Fi의 차단도
  함께 확인한다.
  - `https://cdn.jsdelivr.net` — MediaPipe Tasks Vision JS/WASM
  - `https://storage.googleapis.com` — Pose Landmarker 모델
- iframe 안에서 프리뷰하지 말고 배포 URL을 새 탭에서 직접 연다. iframe은 상위 페이지의
  `allow="camera"` 정책 때문에 권한이 별도로 차단될 수 있다.

### 로컬 자동 점검 결과

- BODY QUIZ 테스트: 4 files, 94 tests 통과
- 전체 테스트: 64 files, 1145 tests 통과
- 프로덕션 빌드: 통과
- `dist/assets/body-quiz`에서 intro, tutorial, elephant/tiger answer asset 확인
- 기존 BODY QUIZ 범위 밖 build warning:
  - `core/remote/session.js`가 `bgm.js`의 미export `toggle`을 import
  - dynamic import/chunk size warning

## 2. QA 체크리스트

### a. 접속 / 환경

- [ ] 테스트 URL이 HTTPS로 열리고 인증서 경고가 없다.
- [ ] `/#/intro?id=body-quiz`가 허브로 튕기거나 빈 화면이 되지 않는다.
- [ ] 인트로 이미지와 `게임 시작` 버튼이 정상 표시된다.
- [ ] `게임 시작` 후 튜토리얼 또는 실제 play scene으로 이동한다.
- [ ] 기존 튜토리얼 완료 브라우저에서는 play scene으로 바로 진입한다.
- [ ] `&tutorial=1` URL에서는 완료 기록과 관계없이 튜토리얼이 표시된다.
- [ ] BODY QUIZ가 허브에 안 보이는 현상이 현재 `wip` 정책임을 테스터가 알고 있다.
- [ ] 배포할 commit에 BODY QUIZ source/assets와 registry 등록이 포함되어 있다.
- [ ] unrelated balloon-festival untracked asset이 배포 commit에 섞이지 않았다.
- [ ] 배포 환경에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`가 설정되어 있다.
- [ ] DevTools Console에 앱 부팅을 막는 uncaught error가 없다.
- [ ] jsDelivr WASM과 Google MediaPipe model 요청이 200으로 완료된다.
- [ ] 첫 접속의 모델 다운로드가 끝날 때까지 카메라 연결 안내가 유지되고 빈 화면이 되지 않는다.
- [ ] 최신 Chrome/Edge 또는 iOS 16.4 이상 Safari에서 실행한다.

### b. 카메라 권한

- [ ] 첫 플레이 진입에서 카메라 권한 팝업이 표시된다.
- [ ] `허용` 선택 후 전면 카메라 영상이 full-bleed 배경으로 표시된다.
- [ ] 영상이 사용자 관점의 거울 방향으로 표시된다.
- [ ] 영상 위에 인트로의 손 커서/PIP가 남지 않는다.
- [ ] `거부` 선택 시 빈 화면 대신 `카메라를 확인해주세요`와 재시도 버튼이 보인다.
- [ ] 사이트 설정에서 카메라를 허용한 뒤 재시도 또는 새로고침으로 복구된다.
- [ ] OS 카메라 권한이 꺼진 경우 안내가 보이고 앱 전체가 멈추지 않는다.
- [ ] 다른 탭·화상회의 앱이 카메라를 점유한 상태에서 오류 안내가 보인다.
- [ ] 게임 처음으로/Home 이동 후 재진입해도 `NotReadableError`나 중복 권한 팝업이 반복되지 않는다.
- [ ] 손 커서 기능이 켜져 있던 사용자는 이동 후 공용 카메라가 계속 공유될 수 있음을 감안한다.
      BODY QUIZ가 별도 스트림을 남기는지 여부는 재진입 실패/중복 영상/PIP 잔류로 판정한다.

### c. 플레이 흐름

- [ ] 상단 왼쪽에 실제 진행도 `QUIZ 1 / 1`이 표시된다.
- [ ] 상단 질문이 `questions.js` 데이터와 일치한다.
- [ ] 좌우에 코끼리와 호랑이가 각각 한 번씩 표시된다.
- [ ] 새 세션/새로고침을 반복하면 정답 위치가 LEFT 또는 RIGHT로 바뀔 수 있다.
- [ ] 정답 위치가 바뀌어도 코끼리를 선택하면 정답으로 판정된다.
- [ ] MOVE LOCK 상태에서는 좌우로 이동해도 답이 확정되지 않는다.
- [ ] 정답 확정 후 positive feedback이 표시된다.
- [ ] 오답 확정 후 과도하지 않은 red feedback이 표시된다.
- [ ] 플레이 중 화면 멈춤, 반복 질문 생성, 동일 답 두 장 표시가 없다.
- [ ] 사용자에게 보이는 countdown timer가 없다.

### d. 스쿼트 카운트 / MOVE ENERGY / MOVE LOCK

- [ ] 시작 상태가 `SQUAT 0/5`, `MOVE ENERGY 0%`, `MOVE LOCK`이다.
- [ ] 앉기만 하고 서지 않으면 1회로 카운트되지 않는다.
- [ ] 정상적으로 앉았다 일어날 때 한 동작당 정확히 1회 증가한다.
- [ ] 작은 흔들림이나 제자리 서기만으로 스쿼트가 증가하지 않는다.
- [ ] 1/5, 2/5, 3/5, 4/5에서 ENERGY가 각각 20%, 40%, 60%, 80%로 표시된다.
- [ ] 5/5에서 ENERGY가 100%가 되고 `MOVE UNLOCK`으로 바뀐다.
- [ ] 5회 이후 추가 스쿼트로 카운트가 5를 넘지 않는다.
- [ ] ENERGY bar가 숫자와 같은 비율로 채워진다.
- [ ] unlock 순간 HUD의 gold/highlight 상태가 명확히 보인다.
- [ ] 운동 pictogram이 깨진 이미지나 emoji가 아니라 white SVG로 보인다.

### e. 좌우 선택

- [ ] 카메라 중앙에 섰을 때 어느 답 카드도 선택 강조되지 않는다.
- [ ] MOVE UNLOCK 후 사용자 기준 왼쪽으로 이동하면 왼쪽 카드가 강조된다.
- [ ] MOVE UNLOCK 후 사용자 기준 오른쪽으로 이동하면 오른쪽 카드가 강조된다.
- [ ] 선택 중인 카드만 커지고 반대 카드는 약해진다.
- [ ] 중앙으로 돌아오면 확정 전 선택 진행이 초기화된다.
- [ ] 한쪽 zone을 약 0.6초 유지해야 답이 확정된다.
- [ ] 경계에서 가만히 있을 때 좌우 강조가 빠르게 깜빡이지 않는다.
- [ ] 화면에 보이는 방향과 판정 방향이 반대로 뒤집히지 않는다.
- [ ] 정답 위치가 랜덤이어도 `correct/wrong` 판정이 답 데이터와 일치한다.
- [ ] 보호자나 다른 사람이 프레임에 들어왔을 때 대상이 갑자기 바뀌지 않는지 기록한다.

- [ ] 패널 바깥 클릭과 ESC로 패널이 닫힌다.
- [ ] 각 음원 버튼 상태가 클릭 후 아이콘에 반영된다.
- [ ] 전체화면 버튼이 지원 브라우저에서 진입/해제된다.
- [ ] exit 버튼을 누르면 즉시 종료되지 않고 확인 팝업이 열린다.
- [ ] exit 팝업을 열 때 hamburger 패널이 함께 열려 있지 않는다.
- [ ] `계속하기`가 팝업만 닫고 같은 문제 상태로 복귀한다.
- [ ] `게임 처음으로`가 BODY QUIZ 인트로로 이동한다.
- [ ] `Home으로`가 Play Zera 허브로 이동한다.
- [ ] 팝업 바깥 클릭과 ESC가 안전하게 계속하기로 동작한다.
- [ ] 메뉴/팝업이 열린 동안 스쿼트·zone 선택·답 유지 시간이 진행되지 않는다.

- [ ] 최소 5분 연속 사용 후 프레임 저하, 발열, 카메라 멈춤 여부를 기록한다.

## 3. 1차 QA 통과 기준

- P0/P1 버그가 없다.
- 한 명의 사용자가 카메라 권한 허용부터 스쿼트 5회, MOVE UNLOCK, 답 확정까지
  도움 없이 한 흐름으로 완료할 수 있다.
- 대상 5개 viewport에서 핵심 UI 잘림과 스크롤이 없다.
- 정답 위치가 어느 쪽이어도 판정이 일치한다.
- 종료/재진입 후 카메라 충돌이나 입력 중복이 없다.

### 심각도 기준

- `P0`: 앱 진입 불가, 카메라/게임 전체가 모든 환경에서 시작되지 않음
- `P1`: 정상적인 한 판 완료 불가, 스쿼트·unlock·정답 판정의 핵심 기능 오류
- `P2`: 특정 기기/조건에서 반복되는 오검출, 레이아웃 잘림, 메뉴 기능 오류
- `P3`: 문구, 미세 정렬, 일시적인 장식/애니메이션 문제
