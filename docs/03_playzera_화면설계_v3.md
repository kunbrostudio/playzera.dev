# 플레이 제라 (Play Zera) 화면 설계 v3

> 폰 본체 + 손 포인터 조작 기준
> 개정일: 2026년 7월 28일 (v1: 6월 / v2: 7월 28일)

---

## 개정 요약 (v2 → v3)

| 항목 | v2 | v3 |
|---|---|---|
| 사이드바 | 좌측 5메뉴 (220px) | **삭제** |
| 계정 · 메뉴 | 좌측 하단 / 사이드바 | **우상단 계정 + 햄버거** |
| 홈 구성 | 히어로 배너 + 그리드 + 미션 | **이어서 하기 레일 + 전체 게임 그리드** |
| 카테고리 | 사이드바 / 구조 | **우상단 필터 버튼 → 팝업** |
| 세로 이동 | 없음 | **하단 4칸 바 (맨위·위·아래·맨아래)** |
| 기준 해상도 | 노트북 가로 | **폰 가로 (모바일 우선)** |
| 조작 | O/X 제스처 | **손 포인터 + 머무르기 / 마우스 / 터치** |

## 전역 원칙

### 기준 해상도
**폰 가로 약 850×390 CSS px.** 노트북·TV는 여기서 확대되는 방향으로 대응한다. 반대로 잡으면 폰에서 다 깨진다.

### 조작 3종
| 입력 | 포커스 | 실행 |
|---|---|---|
| 손 포인터 | 손 위치 | 머무르기 (0.5~1.2초) |
| 마우스 | 호버 | **클릭 즉시** |
| 터치 | — | **탭 즉시** |

같은 화면에서 셋 다 된다. 머무르기는 손에만 적용.

### 화면별 조작 층 ★ v3 초판 정정

> 초판은 "메뉴=포인터 / 게임 중=O/X"로 기술했으나, 구현된 웜업 게임은 반대다. O/X는 화면 전환용이고 게임플레이는 별도 모션을 쓴다. 아래가 실제 기준이다.

| 화면 | 조작 | 선택지 수 | 상태 |
|---|---|---|---|
| 홈 — 게임 그리드 | **손 포인터 + 머무르기** | 20개+ | 신규 |
| 게임 스타트 화면 | **O / X 유지** | 2개 | 구현됨 |
| 카메라 준비 | **O 유지 3초** | 1~2개 | 구현됨 |
| 게임플레이 | **게임별 모션** | — | 구현됨 |
| 게임오버 · 종료 확인 | **O / X 유지 1.5초** | 2개 | 구현됨 |
| 설정 | 터치 · 마우스 전용 | — | 신규 |

**기준은 선택지 개수다.** 두세 개짜리 이지선다는 O/X로 충분하고 이미 잘 돌아간다. 포인터는 O/X로 풀 수 없는 **게임 목록 하나**를 위해 만든다.

이 구분 덕분에 각 게임팩은 자기 스타트 화면을 그대로 유지할 수 있다. 선택지가 "시작 / 뒤로" 둘뿐이라 O/X면 되고, 포인터를 붙일 필요가 없다.

### 머무르기 시간
| 대상 | 시간 | 이유 |
|---|---|---|
| 스크롤 · 페이지 이동 | 0.5초 | 되돌리기 쉬움 |
| 카테고리 선택 | 0.6초 | 목록이 바뀌어 놀랄 수 있음 |
| 게임 카드 | 1.2초 | 잘못 누르면 게임이 시작됨 |

### 타겟 규칙
- 최소 크기 **96×96px**, 간격 최소 12px
- 화면 가장자리 6px에는 타겟 배치 금지 (포인터가 도달 못 함)
- 정밀 조작 UI 금지 — 드래그, 슬라이더, 작은 체크박스

미러링 지연이 얹히면 커서가 손을 늦게 따라온다. 작은 타겟은 못 맞춘다.

### 영역별 사양

| 영역 | 내용 | 동작 |
|---|---|---|
| **좌상단** | PLAY ZERA 로고 | 홈 복귀 |
| **우상단 계정** | 현재 플레이어 / 센터 | 2단계에서 아이 선택 |
| **우상단 햄버거** | 오늘 기록 · 아이 관리 · 설정 · 사용 방법 | 팝업 메뉴 |
| **이어서 하기** | 최근 플레이 게임 (최대 8개) | **좌우 레일** |
| **전체 게임** | 전체 목록 (4열 그리드) | **세로 이동** |
| **필터 버튼** | 현재 필터 표시 | 머무르면 팝업 |
| **하단 바** | 4칸 세로 이동 | 머무르기 0.5초 |

### 사이드바를 없앤 이유

1. **가로 공간** — 220px을 먹으면 카드가 4열에서 3열로 줄어든다. 이 레이아웃에서 가로 폭은 곧 노출되는 게임 개수다.
2. **포인터 도달성** — 화면 왼쪽 끝은 손 포인터로 닿기 가장 불편한 자리다.
3. **넣을 메뉴가 없다** — 현재 필요한 항목은 4개뿐이라 햄버거로 충분하다.

### 우상단에 계정·메뉴를 둔 이유

오른쪽 위 구석은 **손 포인터로 가장 닿기 어려운 자리**다. 설정과 계정은 아이가 건드리면 안 되는 것들이라 불편함이 그대로 안전장치가 된다. 반대로 부모가 폰을 집어서 터치할 땐 아무 문제가 없다.

### 이어서 하기 (좌우 레일)

- 최근 플레이한 게임 순으로 최대 8개
- 화면에 4개 노출, 양끝 화살표로 **한 화면씩(4개) 이동**
- 머무르기 0.5초, **자동 반복 가속 없음**

> 좌우에 가속을 넣지 않는 이유 — 한 번에 4개가 움직이는데 가속까지 붙으면 순식간에 20개가 지나가 아이가 놓친다. 일정한 속도로 한 화면씩이 맞다.

**이 줄이 가장 중요하다.** 아이 대부분은 "어제 하던 거 또 하기"를 한다. 탐색의 대부분이 여기서 끝난다.

### 전체 게임 (세로 그리드)

- 4열 그리드, 2줄 노출
- 좌우 슬라이드 없음 — **화면에서 좌우로 움직이는 것은 '이어서 하기' 하나뿐**
- 세로 이동은 하단 4칸 바로만

### 하단 4칸 바

```
│  ⤒ 맨 위로  │  ▲ 위로  │  ▼ 아래로  │  ⤓ 맨 아래로  │
     (멀리)     (한 줄)    (한 줄)      (멀리)
```

**배치 원칙: 바깥쪽일수록 멀리 간다.** 이동 거리가 버튼 위치와 대응되어 아이가 감으로 익힌다.

- 4칸 모두 항상 표시. 한계에 도달한 방향만 흐려짐(opacity 0.32)
- 화면 맨 아래에 둔 것도 의도 — 팔을 들어올릴 일이 없어 덜 지친다
- **한 줄만 내려가도 즉시 위로 돌아올 수 있다** (v2의 "바닥까지 가야 위로" 문제 해결)

실제로 가장 많이 쓰일 것은 **맨 위로**다. 아래로 몇 번 내려갔다가 "그냥 어제 하던 거 할래" 할 때 이어서 하기로 한 번에 복귀하는 사실상의 홈 버튼.

### 카테고리 팝업

```
┌────────────────────────────────┐
│  어떤 운동을 해볼까?            │
│  ┌────────────┐┌────────────┐  │
│  │ 🎯 전체 20 ││ 🏃 달리기 5│  │
│  └────────────┘└────────────┘  │
│  ┌────────────┐┌────────────┐  │
│  │ 🦘 점프  5 ││ 🧘 균형   5│  │
│  └────────────┘└────────────┘  │
│  ┌────────────┐                │
│  │ 🤝 협동  5 │                │
│  └────────────┘                │
└────────────────────────────────┘
```

- 우상단 필터 버튼에 머무르면 열림
- 타일마다 **해당 태그의 게임 수** 표시 → "달리기 5개구나" 하고 기대가 생긴다
- 머무르기 0.6초로 적용 후 자동 닫힘
- **닫기 버튼 없음** — "전체"가 곧 닫기이자 초기화. 버튼이 하나 줄어드는 편이 4~8세에게 낫다

**태그는 구조가 아니라 렌즈다.** 게임은 항상 전체 목록에 있고, 필터는 보이는 것만 걸러낸다. 한 게임이 여러 태그를 가져도 중복 문제가 없다.

### 게임 카드 ↔ manifest 매핑

| 카드 표시 | manifest 필드 |
|---|---|
| 썸네일 | `thumbnail` |
| 제목 | `title` |
| 태그 (최대 2개) | `tags` |
| 인원 배지 | `players.min ~ players.max` |
| NEW 배지 | `createdAt` 기준 자동 |

### 게임 50개 이후

지금 구조는 40~50개까지 유효하다(4열 × 세로 이동 3~4회). 그 이후엔 **"전체"가 기본값이면 안 되고, 뭔가로 좁혀진 상태가 기본**이 되어야 한다. 태그만 처음부터 성실히 달아두면 그때 무엇으로 좁히든 대응된다. 지금 미리 구조를 꼬을 필요는 없다.

## 화면 2: 플레이어 준비

**URL:** `/#/ready?id=xxx`
**용도:** 누가 플레이하는지 확정 + 카메라 인식 확인

```
┌──────────────────────────────────────────────────────────┐
│  ← 뒤로            🏃 인터랙션 웜업 장애물 피하기          │
│                                                          │
│  ┌────────────────────┐   오늘 플레이할 아이             │
│  │                    │   ┌────┐ ┌────┐ ┌────┐ ┌────┐  │
│  │   카메라 프리뷰    │   │제라│ │지우│ │민준│ │ +  │  │
│  │   (포즈 스켈레톤)  │   └────┘ └────┘ └────┘ └────┘  │
│  │                    │                                  │
│  │  ✅ 인식 좋아요!   │   👋 양팔로 O를 만들면 시작!     │
│  └────────────────────┘                                  │
│                                                          │
│           ⭕ 시작        ❌ 뒤로가기                      │
└──────────────────────────────────────────────────────────┘
```

### 카메라 인식 상태

| 상태 | 표시 | 조건 (`poseEngine.getDistanceHint()`) |
|---|---|---|
| ✅ 인식 좋아요! | 그린 | `'ok'` — 어깨너비 비율 0.12~0.34 (약 1.5~2m) |
| ⚠️ 조금 뒤로 가주세요 | 옐로우 | `'too-close'` |
| ⚠️ 조금 앞으로 와주세요 | 옐로우 | `'too-far'` |
| ❌ 아이가 안 보여요 | 레드 | `isTracking() === false` |

**이 화면이 v3에서 더 중요해졌다.** 가정에서는 세팅을 도와줄 사람이 없다. 카메라가 잘못 놓이면 게임 자체가 안 돌아가므로, 플레이 전에 반드시 확인시키는 게이트 역할을 한다.

### 지연 캘리브레이션 (티어 B에서만)

미러링 환경이면 이 화면에서 1회 수행한다.

```
┌──────────────────────────────────┐
│      화면이 반짝하면 ⭕ 해주세요! │
│                                  │
│              ●                   │
│                                  │
│           1 / 3 회               │
└──────────────────────────────────┘
```

게임처럼 느껴지게 만들어서 거부감을 없앤다. 결과는 `env.latencyMs`로 저장되어 반응속도 보정에 쓰인다.

## 화면 3: 게임 플레이

**URL:** `/#/game?id=xxx`
**표시:** 전체화면 (헤더 숨김)

```
┌──────────────────────────────────────────────────────────┐
│  ● ● ● ● ●      ❤️❤️❤️      320점      09        [⛶]   │
├──────────────────────────────────────────────────────────┤
│                                                          │
│                    [ CANVAS 영역 ]                       │
│                                                          │
│                                              ┌────────┐  │
│                                              │ 카메라 │  │
│                                              │  PIP   │  │
│  ┌────────────────────────┐                  │ ● 인식 │  │
│  │  ⭕ 맞다!    ❌ 아니다! │                  └────────┘  │
│  └────────────────────────┘                              │
└──────────────────────────────────────────────────────────┘
   Space 일시정지 · Esc 종료 · F 전체화면  (3초 후 페이드)
```

### 게임 중에는 포인터를 끈다

**중요.** 게임 진입 시 `pointer.disable()`. 포인터가 살아 있으면 아이의 팔 동작이 UI를 건드린다. 홈으로 돌아올 때 다시 켠다.

플레이 중 종료는 포인터가 아니라 **X 유지 1.5초**로 처리한다(웜업 게임에 이미 구현됨). 팔을 교차한 채 1.5초를 버텨야 해서 우발적으로 발동하지 않는다.

### HUD

| 요소 | 위치 |
|---|---|
| 라운드 핍 | 좌상단 (manifest.rounds 개수) |
| 목숨 | 중앙상단 (게임별 선택) |
| 점수 · 타이머 | 우상단 |
| 카메라 PIP | 우하단 (상시 표시) |
| 제스처 힌트 | 좌하단 |

### 카메라 PIP
- 120×160px, 포즈 스켈레톤 오버레이
- 🟢 인식중 / 🔴 미인식
- 미인식 3초 지속 시 자동 일시정지 + 안내

### 제스처 힌트
`manifest.gestures`를 읽어 자동 렌더. 인식되는 순간 그린으로 펄스.

```
⭕ 맞다!     ❌ 아니다!      ← warmup-obstacle
⭕ 피해!     ❌ 그대로!      ← poop-dodge
```

### 오버레이

**카운트다운** `3 / 준비하세요!`
**라운드 배너** `ROUND 2 / 조금 더 빠르게!`
**판정 팝업** `✅ 잘했어요!` (그린 0.8초) / `💥 아쉬워요!` (레드 0.8초)
**게임 오버** `😵 게임 오버! / ⭕ 다시 하기  ❌ 그만하기`

### 표시 규칙

| 영역 | 1단계 (세션) | 2단계 (아이 누적) |
|---|---|---|
| 게임 성과 | ✅ | ✅ |
| 오늘의 운동 데이터 | ✅ | ✅ |
| "지난번보다 ↑" 비교 | ❌ 숨김 | ✅ |
| 운동 역량 | 당일 1회 (참고값) | 누적 (신뢰값) |

**반응속도 표시는 보정값(`reaction_adj_ms`)을 쓴다.** 미러링 환경에서 원본을 그대로 보여주면 실제보다 200ms 느리게 나온다.

## 디자인 가이드라인

### 핵심 방향
- **어둡고 몰입감 있는 게임 UI** — 배경 #0f1729
- **폰 가로가 기준** — 여기서 확대되는 방향으로 대응
- **큰 타겟, 넉넉한 간격** — 포인터 + 미러링 지연 대응
- **O/X 아이콘은 어디서나 동일하게** — 아이가 학습하는 언어이므로 형태·색·위치 일관성
- **귀엽지만 과하지 않게**

### 폰트
Pretendard — 게임 제목 900 / HUD 숫자 800 / 본문 400~600

### 색상 사용 규칙
| 색상 | 용도 |
|---|---|
| #00CF00 그린 | 성공, O 동작, 액션, 포인터·머무르기 링, 인식 양호 |
| #ffe600 옐로우 | 라운드 배너, 강조 숫자, NEW 배지, 주의 |
| #ff4757 레드 | 위험, 충돌, 인식 실패 |
| #e8f4f8 화이트 | 본문 |
| #8892a4 그레이 | 보조, 비활성 |

> ⚠️ **X 동작 아이콘은 레드를 쓰지 않는다.** 실패 판정도 레드라서, X를 레드로 두면 아이가 "X = 틀린 것"으로 오해한다. X는 중립적 선택지이기도 하므로 화이트/그레이 계열로 분리한다.

### 구현 우선순위
1. 홈 (게임 허브) — 레이아웃 확정됨
2. 손 포인터 + 머무르기 링 (전 화면 공통)
3. 플레이어 준비 (카메라 게이트)
4. 게임 플레이 HUD
5. 게임 결과
6. 설정 (포인터·O/X 테스트)
7. 오늘 기록
8. 아이 관리 (2단계)
9. 보조 컨트롤러 (선택)

## 미결정 항목

1. **다인 플레이(2~4명) 결과 화면** — 2~4명 결과를 한 화면에 어떻게 배치할지 미설계
2. **플레이어 이름 입력 방식** — 매번 타이핑은 번거로움. 2단계 아이 등록 전까지의 임시 UX 필요
3. **머무르기 시간 기본값 1.2초** — 가설. 실제 아이들 반응으로 확정 필요
4. **게임 50개 이후 홈 기본 상태** — "전체"가 아닌 무엇으로 좁힐지
5. **햄버거 메뉴를 손 포인터로 열 수 있게 할지** — 안전장치로서 일부러 어렵게 둘지, 접근성으로 열어둘지
