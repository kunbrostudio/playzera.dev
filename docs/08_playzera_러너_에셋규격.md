# 러너 게임 에셋 규격

달리며 장애물을 피하는 러너 엔진(`src/games/runner/`)은 **테마 폴더만 갈아 끼우면**
다른 게임이 된다. 아래 규칙과 목록은 **모든 러너 테마에 공통**이고, 물건 이름만 테마마다 다르다.

| 테마 | 게임 id | 폴더 | 상태 |
|---|---|---|---|
| 우주 (인터랙션 웜업) | `warmup-obstacle` | `public/assets/runner/space/` | 완성 |
| 정글 탐험대 | `jungle-run` | `public/assets/runner/jungle/` | **진짜 9장 + 도형 66장** — 제작 중 |
| 쥬라기 대탐험 | `jurassic-run` | `public/assets/runner/jurassic/` | **진짜 10장 + 도형 65장** — 제작 중 |

목록의 정본은 각 테마의 **`src/games/runner-<테마>/theme.json`**이다. 이 문서와 어긋나면
JSON이 맞다. 파일명을 바꾸고 싶으면 JSON의 값만 고치면 된다 — **코드는 파일명을 모른다.**

넣을 곳은 위 표의 폴더 아래 `image/`(전부 `.png`)와 `audio/`.
진짜 그림을 같은 이름으로 덮어쓰면 그 자리부터 바뀐다. 한 장씩 교체해도 게임은 계속 돈다.

> 도형 플레이스홀더는 `tools/makePlaceholders.mjs`가 만든다. **사람이 넣은 진짜 그림은
> `--force`로도 덮지 않는다** — 폴더의 `.placeholders` 목록에 있는 파일만 다시 만든다.

아래 본문의 파일명은 **정글 기준**이다. 쥬라기 대응표는 맨 끝에 있다.

## 먼저 — 여섯 가지 규칙

**① 바닥에 닿는 것은 이미지 아래쪽 끝까지 그린다.**

엔진은 스프라이트의 **맨 아래를 지면**으로 보고 그 자리에 그림자를 깐다.
아래에 투명 여백이 있으면 그만큼 공중에 뜬다. 위쪽 여백은 상관없다.

**② 정면에서 살짝 위를 올려다본 각도.**

카메라는 트랙 한가운데에서 앞을 본다. 좌우 프롭은 엔진이 **오른쪽 것을 자동으로
뒤집어** 안쪽을 보게 한다. 그러니 그림은 **왼쪽에 놓인다고 가정**하고 그린다
(비스듬한 것은 오른쪽을 향하게).

**③ 원본 크기는 안 맞춰도 된다. 맞춰야 하는 것은 비율이다.**

코드가 정하는 건 **세로(`h`) 하나**고 가로는 원본 비율대로 따라간다.

```js
const h = p.h * scale;                    // theme.json의 h
const w = h * (img.width / img.height);   // 가로는 원본 비율
```

그래서 야자수를 500×1000으로 주든 1000×2000으로 주든 화면에서는 똑같다.
**가로세로 비율이 달라질 때만** 화면에서의 폭이 바뀐다.

원본은 **긴 변 1000px**(하늘·타이틀만 1600px). 우주 에셋도 이 규칙이고 실제 크기는
제각각이다 — `char_*` 692×1000, `bg_tower_*` 829~992×1000, `obs_*` 1000×468~851.

| 물건 | 권장 비율 (가로:세로) |
|---|---|
| 캐릭터 13장 | 0.69 — **13장이 전부 같아야** 애니메이션이 덜컥거리지 않는다 |
| 배경 프롭 (야자수·유적·토템) | 0.83 ~ 1.0 |
| 낮은 것 (연못·덤불·꽃) | 1.3 ~ 1.6 |
| 장애물 상자 | 1.2 ~ 1.3 |
| 통나무·덩굴 | 2.0 ~ 2.1 |
| 포즈 사인판 | 1.8 ~ 2.1 |
| 능선 `bg_jungle_ridge` | 5 ~ 6 (좌우로 이어 붙인다) |
| 하늘 `bg_sky` | 1.78 (1600×900) |

**④ 위아래 투명 여백을 최소로.**

`h`는 **이미지 전체 높이** 기준이다. 위에 20%가 비어 있으면 실제 물건은 `h`의 80%만
차지한다. 우주 에셋의 위 여백이 3~21%로 제각각이라 `theme.json`의 `h` 값도 거기
맞춰져 있다. 정글 여백이 많이 다르면 **`h` 값을 다시 잡으면 된다** — JSON 한 줄씩이다.

**⑤ 그림자는 그리지 말 것.**

엔진이 원근에 맞춰 타원 그림자를 따로 깐다. 그림에 그림자가 있으면 두 겹이 된다.

**⑥ 투명 배경(알파) 필수.** 흰 배경으로 오면 사각형이 보인다.

> **글로우(발광 헤일로)는 넣지 말 것.** 컨셉 시트용으로 뒤에 깔린 빛은 게임 안에서
> 초록 바닥 위에 **네모난 빛 자국**으로 남고, 물건 아래로 번진 만큼 공중에 뜬다.
> 1차로 받은 9장이 그랬고, 알파 128 기준으로 잘라내 넣었다 — 원본에 없는 편이 낫다.

## 색 — 참고 이미지에서 뽑은 것

`theme.json`의 `world.palette`에 이미 들어 있다. 그림을 이 색조에 맞춰 주면 트랙과
바닥이 따로 놀지 않는다.

| 자리 | 색 |
|---|---|
| 잔디 (트랙 밖) | `#7fc93f` → `#3d8a1e` (멀수록 밝게) |
| 트랙 바닥 | `#b8823a` (황토) |
| 트랙 테두리 | `#f2c94c` 금색 |
| 연석 | 윗면 `#c98c31` · 그늘 `#6b4212` |
| 레인 라인 | 연두 네온 `rgb(168,240,74)` |
| 전진 화살표 | 노랑 `rgb(255,214,60)` |
| 하늘 | `#57b6ef` |

> **트랙과 바닥은 색상(초록 vs 황토)으로 갈린다.** 명도로 가르면 오브젝트가 설 자리를
> 잃고 떠 보인다 — 우주 테마에서 실제로 겪었다.

`public/assets/runner/_shared/`에 한 벌만 있고 세 게임이 같이 쓴다.

`signs_left` · `signs_right` · `signs_up`(점프) · `signs_down`(숙이기) · `signs_pose`

## 파일 크기

`docs/04`의 에셋 다이어트에서 정한 기준을 그대로 따른다.

- 스프라이트 **최대 1000px**, 배경 **최대 1600px**
- 화면에서 210px로 그려지는 것을 1086×1448로 받아 10MB를 날린 적이 있다
- 다 넣고 나면 `npm run build` 후 폴더 크기를 확인한다

## 들어온 뒤 확인

```bash
npm run world -- jungle.png 6 runner-jungle   # 배경만 PNG로 뽑아 본다
npm test                                       # 선언한 그림이 다 있는지 검사
npm run dev                                    # #/play?id=jungle-run
```

`npm test`의 `runnerTheme.test.js`가 **선언했는데 없는 파일**을 잡는다.
반대로 폴더에만 있고 `theme.json`에 없는 파일은 그냥 안 쓰인다 — 쓰이게 하려면
JSON의 프롭 목록에 한 줄 추가하면 된다.
