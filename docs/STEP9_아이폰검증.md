# 아이폰 Safari 검증 체크리스트

> 기준일 2026-08-04 (홈 구조 변경 반영) · 대상 브랜치 `integrate-warmup`

v3에서 **"폰이 본체"**로 방향을 잡았다. 아이폰 사용자에게는 **모든 브라우저가 Safari(WebKit)** 다 — iOS의 크롬·파이어폭스도 내부 엔진은 WebKit이라 "크롬으로 우회"가 통하지 않는다. **Safari는 부차적 대상이 아니라 주 타깃이다.**

지금까지 검증은 전부 맥 크롬에서 했다. 이 문서는 그 사이 벌어진 간격을 메우기 위한 것이다.

---

## 0. 프리뷰 올리기

로컬 `npm run dev`로는 아이폰에서 카메라가 안 열린다. `getUserMedia`는 **보안 컨텍스트(HTTPS)** 를 요구하고, `localhost`는 그 기기 자신에게만 보안 컨텍스트다.

```bash
npm test && npm run build      # 먼저 통과시킨다
git add -A
git commit -m "홈 구조 개편: 한 줄 레일 + 전체 보기 팝업 · 카테고리 셀렉트 · 레이아웃 3건 수정"
git push
```

Netlify 대시보드 → **Site settings → Build & deploy → Branch deploys** →
"Let me add individual branches"에서 `integrate-warmup` 추가.

배포되면 주소는 이 모양이다.

```
https://integrate-warmup--<사이트이름>.netlify.app
```

`main` 자동 배포는 그대로라 **운영본은 건드려지지 않는다.**

## 1. 먼저 확인할 것 — 여기서 막히면 나머지는 의미 없다

| 확인 | 통과 기준 | 실패하면 |
|---|---|---|
| 홈이 뜨는가 | 히어로 + 카드 한 줄 | 빌드·경로 문제 |
| **"✋ 손으로 고르기" 버튼이 보이는가** | 보임 | **iOS 16.4 미만이거나 WASM SIMD 미지원** — 콘솔에 `손 포인터 미지원` 이유가 찍힌다 |
| 버튼을 누르면 카메라 권한 팝업 | 뜬다 | HTTPS가 아니거나 Safari 설정에서 카메라 차단 |

> 버튼이 아예 안 보이면 그 기기는 **지원 하한선 아래**다. iOS 버전을 기록해두자. 이게 우리가 지원을 포기할 선을 정하는 근거가 된다.

## 2. 손 포인터

| 확인 | 비고 |
|---|---|
| 손을 어깨 위로 들면 커서가 나오는가 | |
| 커서가 심하게 떨리지 않는가 | 떨리면 `pointer.js`의 One Euro `minCutoff`·`beta` 조정 |
| 카드 위 1.2초로 **게임이 바로 시작되는가** | 선택만 되고 멈추면 이전 동작이 남은 것 |
| 팔을 내리면 커서가 사라지는가 | |
| **다른 화면으로 갔다 돌아와도 다시 켜지는가** | iOS는 제스처 없이 `getUserMedia`를 거부한다 → **첫 탭 한 번**에 켜지도록 해뒀다. 아무 데나 한 번 눌러야 켜지면 정상 |

## 2-1. 홈 조작 — 8/4에 구조가 바뀐 부분 ★ 이번 검증의 핵심

하단 4칸 바를 없애고 **한 줄 레일 + 전체 보기 팝업**으로 바꿨다. 여기는 아직 실기기에서 한 번도 안 돌려봤다.

| 확인 | 통과 기준 | 실패하면 |
|---|---|---|
| 레일 좌우 화살표(◀ ▶)에 손이 닿는가 | 닿음 | 이전에 하단 바가 못 닿았던 문제의 재발 — `pointer.js`의 `BOX_*` 값 |
| 카드에 손을 올리면 **히어로가 즉시 바뀌는가** | 바로 바뀜 | `pz-pointer-enter` 미발화 |
| `☷ 전체 보기`가 손으로 열리는가 | 열림 | |
| 팝업의 ▲▼ 스크롤 버튼에 손이 닿는가 | 닿음 | |
| 팝업에서 카드를 **누르면 바로 게임으로 들어가는가** | 인트로 진입 | 홈으로 돌아오면 `launch` 미적용 |
| `⚙ 전체 ▾`를 누르면 **버튼 바로 아래로** 목록이 펼쳐지는가 | 펼쳐짐 | 뒤에서 열리면 z-index 회귀 |
| 목록에서 카테고리를 고르면 그 자리에서 필터가 걸리는가 | 걸림 | |
| 카드 제목·태그가 보이는가 | 보임 | 썸네일만 보이면 `grid-auto-rows` 회귀 |

## 4. 화면

**가로 모드가 기본 자세다.** TV 미러링은 폰 화면을 그대로 복사하므로, 세로로 들면 TV 가운데 세로 띠만 뜬다. 가로로 눕혀야 TV를 채운다.

| 확인 | 비고 |
|---|---|
| 가로 모드에서 노치에 버튼이 가리지 않는가 | `env(safe-area-inset-*)` 적용함 |
| **가로 모드에서 팝업의 카테고리가 셀렉트 박스로 바뀌는가** | `max-height: 620px`에서 칩 줄을 접는다 |
| **가로 모드에서 ▲▼ 버튼이 위 요소와 겹치지 않는가** | 겹치면 `.pz-scroll-btn`의 `flex: 1 1 0` 회귀 |
| 카드에 손을 올렸을 때 맨 윗줄 머리가 잘리지 않는가 | 잘리면 그리드 `padding-top` 회귀 |
| 주소창이 나타났다 사라져도 아래가 잘리지 않는가 | `100dvh` 폴백 적용함 |
| 게임 화면에서 스크롤 바운스가 없는가 | |

## 5. 성능·발열 — 실패해도 "안 되는 것"은 아니지만 기록해둘 것

| 항목 | 기준 |
|---|---|
| 콘솔에 `GPU delegate 실패 → CPU로 재시도` | 있으면 CPU로 도는 중 |
| 게임 중 체감 프레임 | 20fps 이상 |
| 20분 연속 플레이 시 발열 | |
| 미러링(AirPlay) 중에도 카메라가 유지되는가 | **티어 B의 전제인데 검증된 적이 없다** |

> 아이폰에서 콘솔을 보려면 맥의 Safari → 개발자 메뉴 → 기기 이름으로 연결한다.
> (아이폰 설정 → Safari → 고급 → 웹 속성(웹 인스펙터) 켜기)

## 7. 통과했다면 — 배포 전환

여기까지 통과해야 `main`을 건드린다. **프로덕션 주소(`curious-dodol-c6e9f0.netlify.app`)는 아직 7월 2일 코드**라, 병합하는 순간 허브가 첫 화면이 된다.

```bash
git checkout main
git pull
git merge integrate-warmup
npm test && npm run build      # 병합 후 한 번 더
git push
```

**병합 직후 프로덕션에서 확인할 것** — 프리뷰와 프로덕션은 도메인이 달라서 갈릴 수 있는 게 셋 있다.

| 확인 | 왜 갈리는가 |
|---|---|
| 루트 주소가 허브로 뜨는가 | 캐시된 옛 `index.html`이 남아 있으면 옛 화면이 나온다 → 하드 새로고침 |
| 카메라 권한이 다시 물어보는가 | 권한은 **출처(origin)별**이다. 프리뷰에서 허락한 게 프로덕션에 따라오지 않는다 |
| **더미 게임 18개가 안 보이는가** | `import.meta.env.DEV`에서만 들어간다. 프로덕션에 뜨면 조건이 새는 것 |
| 기록이 Supabase에 쌓이는가 | 한 판 하고 `game_results`에 행이 느는지 |
